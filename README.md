# file-based-db

Лабораторная работа №2. Файловая база данных «Каталог скинов Dota 2» на Java с интерфейсом на Swing.

## Предметная область

В базе хранятся скины для героев Dota 2. Чаще всего скин ищут по номеру или смотрят все скины одного героя, поэтому кроме индекса по ключу `id` есть индекс по полю `hero`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `int` | ключ, уникальный, больше 0 |
| `name` | `String` | название, до 40 символов |
| `hero` | `String` | герой, до 30 символов |
| `rarity` | `String` | редкость (Common … Arcana), до 15 символов |
| `price` | `double` | цена в долларах, не меньше 0 |
| `tradable` | `boolean` | можно ли обменять |

Пример записи: `1042 | Manifold Paradox | Phantom Assassin | Arcana | 34.50 | да`.

## Архитектура

```
MainWindow (Swing)
      │
   Database ─────────────┬──────────────────┐
      │                  │                  │
  DataFile         PrimaryIndex       SecondaryIndex
  skins.db          skins.pidx          skins.sidx
  записи            id → ячейка         герой → первая ячейка
```

- `Skin` — запись и её чтение/запись в файл;
- `DataFile`, `PrimaryIndex`, `SecondaryIndex` — каждый работает со своим файлом;
- `Database` — все операции базы, связывает три файла;
- `MainWindow`, `SkinTableModel` — интерфейс;
- `XlsxExporter` — экспорт в Excel (Apache POI);
- `Benchmark` — замеры времени.

Интерфейс вызывает только методы `Database` и с файлами напрямую не работает.

## Устройство файлов

Все файлы бинарные, доступ через `RandomAccessFile` по смещению. В памяти хранятся только заголовки файлов.

**skins.db.** Заголовок 16 байт (метка, число ячеек, число записей, первая свободная ячейка), затем ячейки по 192 байта. Адрес ячейки `i`: `16 + i * 192`.

| Байты | Поле |
|---|---|
| 0 | статус (1 — занята, 0 — свободна) |
| 1–4 | `id` |
| 5–84 | `name` |
| 85–144 | `hero` |
| 145–174 | `rarity` |
| 175–182 | `price` |
| 183 | `tradable` |
| 184–191 | предыдущая и следующая ячейки того же героя |

Удалённая ячейка помечается свободной и попадает в список свободных ячеек, новая запись сначала занимает её.

**skins.pidx, skins.sidx.** Хеш-таблицы с линейным пробированием. Слот: состояние (пустой / занятый / удалённый), ключ (`id` или имя героя) и номер ячейки в `skins.db`. При заполнении больше 70% таблица удваивается. Скины одного героя связаны двусвязным списком внутри `skins.db`, в `skins.sidx` хранится только первая ячейка.

## Тесты скорости

Класс `Benchmark` заполняет базу n случайными скинами (120 героев) и измеряет среднее время операций. Компьютер: MacBook Air (Apple Silicon), Java 21.

<!-- вставить числа из вывода Benchmark -->

n |   add, мкс | find id, мкс | hero, мкс/зап | rarity, мс | del id, мкс
---|---|---|---|---|---|
1000 |      440,7 |         73,4 |          75,9 |       69,0 |       112,5
10000 |      429,0 |         73,1 |          71,3 |      693,1 |       109,1
50000 |      407,0 |         73,6 |          71,3 |     3472,8 |       110,3
100000 |      413,4 |         74,5 |          71,3 |     6925,8 |       108,3

Сложность операций (n — записей в базе, k — найденных):
| Операция | Сложность |
|---|---|
| добавление, поиск, удаление и изменение по `id` | O(1) в среднем |
| поиск по герою / удаление по герою | O(1 + k) / O(k) |
| поиск и удаление по другим полям | O(n) |
| backup, восстановление, экспорт | O(n) |

Время операций по `id` и по герою почти не меняется с ростом базы, а поиск по `rarity` растёт пропорционально n, потому что индекса по этому полю нет и проверяется каждая ячейка.

## Запуск

Нужны JDK 21 и Maven.

```
mvn compile exec:java
```

Замеры:

```
mvn compile exec:java -Dexec.mainClass=ru.dota.skins.Benchmark
```
